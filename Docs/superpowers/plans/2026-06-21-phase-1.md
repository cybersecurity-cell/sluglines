# Sluglines Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a production-ready, information-first Sluglines website with secure Supabase accounts, verified content, complete automated checks, and a healthy Vercel production deployment.

**Architecture:** Next.js App Router server components consume typed repository functions backed by Supabase. Supabase Auth and PostgreSQL RLS enforce user isolation; server actions recheck authorization for mutations. Public content uses provenance and freshness fields, while authenticated preferences and reports stay private.

**Tech Stack:** Next.js 16.2.x, React 19.2.x, TypeScript, Tailwind CSS, Supabase PostgreSQL/Auth/SSR, Vitest, Testing Library, axe-core, Playwright, GitHub Actions, Vercel.

## Global Constraints

- Preserve unrelated user changes and never commit credentials, personal exports, database dumps, or private keys.
- Use original copy; the supplied documents and competitor material are research inputs only.
- Do not publish identifiable commuters, readable license plates, outdated operational diagrams, or uncertain-rights assets.
- Every operational record exposes source, verification status, and last-reviewed date.
- Middleware/proxy is never the sole authorization gate; server code and RLS revalidate access.
- Chatbot, voice, check-ins, live counts, notifications, social ingestion, and native mobile apps are excluded.
- Production promotion is allowed only after all required checks and browser verification pass.
